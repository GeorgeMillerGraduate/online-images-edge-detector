From light to structure.

One image, three filters

The image is processed locally at a maximum longest side of 960 pixels. Transparent areas are composited onto white. Grayscale uses 0.2126 R + 0.7152 G + 0.0722 B on browser-decoded channel values. This is an educational approximation, without linear-light colour conversion.

  • Sobel: optional separable Gaussian smoothing, 3×3 horizontal and vertical derivatives, Euclidean magnitude divided by four and clipped to 255, a response threshold, then display gain.
  • Canny: the same smoothing and gradients, four-direction non-maximum suppression, double thresholds and 8-connected hysteresis. Weak responses survive only if connected to a strong response. This local implementation is not claimed to be bit-identical to OpenCV.
  • Centre–surround: the mean in a uniform circular disc minus the mean in a concentric surrounding annulus. ON keeps positive responses, OFF keeps negative responses, Both takes the absolute value. Thresholding precedes gain. The outer radius is always greater than the inner radius.

The centre–surround filter illustrates spatial antagonism inspired by retinal receptive fields. It is neither a complete retinal model nor a detector specifically for circular objects. It uses hard disc/ring weights, rather than a Difference of Gaussians. The diagram is schematic; + and − show the ON-centre convention and reverse for OFF.

Gaussian convolution replicates edge pixels. Sobel and Canny leave the outer one-pixel border at zero. Circular regions at image boundaries are truncated and separately normalised by their available pixel counts. The measured nonzero fraction describes the chosen filter response, not a universal estimate of the number of true edges.

George Miller’s scan orders

The reveal priorities are JavaScript adaptations of George Miller’s supplied Java Mandelbrot project, copyright 2025. The original MIT notice is retained in SCANORDER-LICENSE.txt. Original reference classes are included in scanorder-source/, for example RadialOrderer.java.

Available orders: Simple, Radial, Spiral, Diamond, Angular, Flower, Square spiral, Triangle XOR, XOR and Pythagoras. Pythagoras retains the original bitwise AND priority x & y; it is not a Euclidean distance. Spiral preserves Java’s truncation toward zero. Equal priorities preserve row-major order, matching stable Java sorting. Bands, petals and spiral thickness are adjustable. The reveal moves through sorted pixels at a steady fraction per second: radial motion therefore has a changing geometric speed.

Only display order changes. Every scan produces exactly the same final filtered result. Backward scrubbing restores original pixels. Palette changes preserve progress. Filter or scan changes reset to the photograph and prepare a new result. The complete edge map is exported even when the on-screen reveal is paused halfway.

Privacy & limits

Uploads remain in the page’s memory; they are not uploaded to a service. Supported inputs: PNG, JPEG and WebP, up to 20 MB and 40 megapixels before resizing. A worker performs filtering and sorting. Large inputs still require browser decoding before the size check and can briefly use substantial memory. No API key, external image-processing runtime or Java installation is needed. Serve through HTTP(S), rather than opening index.html directly, so workers load correctly.
